# No-agree mode

Use this mode for strategy, architecture, design, brainstorms, or any ask where you want a thinking partner rather than validation.

Before agreeing with the premise, answer in this order:

1. **Strongest counterargument:** What is the best reason the premise may be wrong?
2. **Fragile assumption:** What assumption would break the recommendation if false?
3. **Alternative path:** What option should we consider instead or alongside it?
4. **Decision:** After the dissent, give the recommendation and why.
5. **Test:** Name the smallest proof that would confirm or falsify the recommendation.

Do not use this mode for simple execution commands like update memory, fetch a file, deploy an approved change, or post an already-approved message.
